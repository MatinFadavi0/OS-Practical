# آزمون‌های عمومی تمرین دوم

[English](README.en.md)

از ریشهٔ مخزن اجرا کنید:

```sh
make -C assignments/hw02/q2 clean
make -C assignments/hw02/q2 CC=gcc
python3 tests/hw02/test_langar.py
```

کد اولیه باید ساخته شود و فقط از `cli_usage` عبور کند: **۵ از ۱۰۰**.
شکست سایر آزمون‌ها مربوط به بخشی است که باید خودتان پیاده‌سازی کنید.

## امتیاز عملکردی سؤال دوم — مجموع ۱۰۰

- `cli_usage`: پنج امتیاز؛ دستور ناقص، جداکننده و زیردستور نامعتبر.
- `absolute_execution`: پنج امتیاز؛ اجرای مسیر مشخص و خروجی بدون پیام اضافی.
- `path_lookup`: پنج امتیاز؛ جست‌وجو در PATH تعیین‌شدهٔ آزمون.
- `argument_boundaries`: ده امتیاز؛ فاصله، مقدار خالی، UTF-8 و نویسه‌های معمول.
- `stdin_inheritance`: پنج امتیاز؛ دریافت ورودی بدون تغییر.
- `stdout_stderr`: پنج امتیاز؛ جدایی خروجی استاندارد و خطا.
- `working_directory`: پنج امتیاز؛ حفظ پوشهٔ کاری فراخواننده.
- `environment`: پنج امتیاز؛ وراثت محیط.
- `direct_child`: پانزده امتیاز؛ متفاوت بودن PID دستور و لنگر و برابری PPID دستور با PID لنگر.
- `parent_waits`: ده امتیاز؛ زنده ماندن پدر هنگام انتظار فرزند برای ورودی.
- `normal_exit_status`: ده امتیاز؛ کدهای عادی ۰، ۷، ۴۲ و ۲۵۵.
- `signal_exit_status`: پنج امتیاز؛ تبدیل SIGTERM به مقدار ۱۴۳.
- `command_not_found`: پنج امتیاز؛ برنامه یا مسیر ناموجود، مقدار ۱۲۷ و stderr.
- `permission_denied`: پنج امتیاز؛ فایل بدون مجوز اجرا، مقدار ۱۲۶ و stderr.
- `not_a_directory`: پنج امتیاز؛ خطای ENOTDIR، مقدار ۱۲۷ و stderr.

هر مورد با عبور از همهٔ بررسی‌های داخل آن، امتیاز مشخص‌شده را می‌گیرد.
این امتیاز صرفاً عملکردی است و کل نمرهٔ درس نیست. الزامات کد و توابع و
توضیح‌ها جداگانه بررسی می‌شوند و گزارش و ویدیو الزامی‌اند. مدیریت شکست
منابع و استفادهٔ واقعی از waitpid و دریافت وضعیت فرزند در کد بررسی می‌شوند؛
آزمون رفتاریِ انتظار، اثبات استفاده از تابع خاصی نیست. ورودی ارزیابی نهایی
ممکن است متفاوت باشد، اما قابلیت‌ها و وزن‌های مشخص‌شده ثابت می‌مانند.

## ثبت خروجی و نتیجهٔ ماشینی

برای ثبت هر دو خروجی و حفظ وضعیت واقعی اجرای آزمون:

```sh
python3 tests/hw02/test_langar.py > assignments/hw02/q2/test-results.txt 2>&1
status=$?
cat assignments/hw02/q2/test-results.txt
echo "$status"
```

خروج با ۰ یعنی همهٔ آزمون‌ها موفق بوده‌اند؛ ۱ یعنی شکست عملکردی و ۲ یعنی
اشکال در آماده‌سازی، مانند نبودن برنامه یا کامپایلر. خروجی اجرای ناموفق را
هم می‌توانید تحویل دهید؛ گزارش موفقیت ساختگی تهیه نکنید.

برای اجرای آزمون روی یک تحویل استخراج‌شده و ذخیرهٔ JSON:

```sh
python3 tests/hw02/test_langar.py --binary /path/to/submission/q2/langar --json /tmp/hw02-result.json
```

خروجی JSON شامل `score`، `total` و برای هر آزمون، `id`، `points`، `earned`،
`passed` و `error` است؛ ابزار درس می‌تواند نتایج چندین تحویل را با همین
ساختار جمع‌آوری کند. آزمون‌ها از فایل آزمون تحویلی دانشجو مستقل‌اند.
گزینهٔ `--cc gcc` کامپایلر برنامهٔ کمکی آزمون را مشخص می‌کند.

برنامهٔ probe فقط بار کاری آزمون است و راه‌حل لنگر نیست. برای معماری جاری
در پوشهٔ موقت کامپایل می‌شود. هر اجرای آزمون مهلت پنج‌ثانیه‌ای دارد و نسخهٔ
انتشار روی لینوکس بررسی می‌شود. آزمون انتظار از نقطهٔ آمادگی و ورودی برای
هماهنگی استفاده می‌کند و به حدس مدت sleep متکی نیست. پردازه‌های متعلق به
آزمون پس از پایان یا شکست پاک‌سازی می‌شوند.
